### 🟡 Importantes (3)

#### 1. Dependencia No Utilizada: `next-recaptcha-v3`
**Impacto:** Bundle size innecesariamente grande
**Ubicación:** `package.json`

```json
"next-recaptcha-v3": "1.5.3"  // ← NO USADO
```

**Evidencia:** No hay referencias en el código
```bash
grep -r "next-recaptcha-v3\|ReCaptcha" **/*.{ts,tsx} → 0 resultados
```

**Acción recomendada:**
```bash
pnpm remove next-recaptcha-v3
```

**Ahorro estimado:** ~50KB en bundle size

---

#### 2. Uso Excesivo de `force-dynamic`
**Impacto:** Rendimiento y costos de servidor
**Ubicación:** 84 archivos con `export const dynamic = 'force-dynamic'`

**Problema:**
- La mayoría de páginas están marcadas como dinámicas
- Esto previene Static Site Generation (SSG)
- Aumenta latencia y costos de servidor en Vercel

**Páginas que podrían ser estáticas:**
- `/about`
- `/faq`
- `/servicios/bodas`
- `/servicios/fiestas`
- `/servicios/empresas`
- `/servicios/discomovil`
- Páginas de blog

**Recomendación:**
Solo usar `force-dynamic` cuando realmente necesario:
- Páginas con datos en tiempo real
- Páginas con autenticación
- Admin dashboard

**Ahorro estimado:**
- 60-80% reducción en costos de función
- 200-300ms mejora en TTFB (Time To First Byte)

---

#### 3. Console.log en Producción
**Impacto:** Seguridad y rendimiento
**Ubicación:** 104 ocurrencias en 22 archivos

**Archivos problemáticos:**
- `prisma/seed.ts` - 42 console.log
- `scripts/monitor.ts` - 25 console.log
- `hooks/usePublicData.ts` - 5 console.log
- `app/components/pwa/PWAProvider.tsx` - 4 console.log
- Y más...

**Problema:**
- Expone información sensible en consola del navegador
- Degrada rendimiento en producción
- Ya existe `lib/logger.ts` con mejor structured logging

**Acción recomendada:**
Reemplazar todos los `console.log` con el logger:

```typescript
// ❌ Antes
console.log('User data:', user);

// ✅ Después
import { log } from '@/lib/logger';
log.info('User data loaded', { userId: user.id });
```

**Script de migración automática:**
```bash
# Buscar y reportar
grep -r "console\\.log" app/ lib/ --include="*.ts" --include="*.tsx"
```

### 🟢 Mejoras Menores (6)

#### 4. Optimización de Imágenes
**Impacto:** Rendimiento y SEO
**Tamaño actual:**
- `/public/img`: **279MB**
- `/public/video`: 46MB (OK)

**Problema:**
El 88% del peso está en imágenes, muchas sin optimizar.

**Recomendaciones:**
1. **Convertir JPG → WebP/AVIF:**
   ```bash
   # Herramienta: squoosh-cli o sharp
   npx @squoosh/cli --webp auto public/img/**/*.jpg
   ```

2. **Comprimir imágenes:**
   - Portfolio: Calidad 80-85%
   - Thumbnails: Calidad 75%
   - Hero images: Calidad 85-90%

3. **Lazy loading:**
   Verificar que todas las imágenes usen `loading="lazy"`

**Ahorro estimado:**
- 150-200MB reducción en tamaño
- 30-40% mejora en Page Speed Insights
- Reducción de costos de CDN/bandwidth
